# 标签字母、编号与数据流程入门

## 1. `LABELS` 是什么

正确变量名是 `config.LABELS`。它列出模型允许回答的类别，列表顺序有实际意义。

本项目做的是“序列标注”：不是给整句只选一个答案，而是给句子里的每个有效位置贴标签。像给快递地址用不同颜色的笔划分省、市、道路和门牌号。

“实体”就是我们想单独抽出的那段有意义的文字，例如“浙江省”。“实体类型”是省份；“实体边界”是从“浙”开始，到“省”结束。

`B-prov` 同时表达两件事：这个字位于某段实体的开头；这段实体属于省份。

## 2. `B/I/E/S/O` 分别是什么意思

当前标签方案通常称为 BMES 或 BIOES，核心含义如下：

| 字母 | 英文 | 中文含义 | 例子 |
| --- | --- | --- | --- |
| `B` | Begin | 一个多字实体的开始 | “浙江省”的“浙” |
| `I` | Inside | 同一个实体的内部 | “浙江省”的“江” |
| `E` | End | 同一个实体的结束 | “浙江省”的“省” |
| `S` | Single | 整个实体只有一个字 | 一个单字实体，具体类型须在标签表中有对应 `S-*` |
| `O` | Outside | 不属于任何目标实体 | 无关标点或文字，具体取决于标注规则 |

注意 `O` 是英文字母 O，不是数字 0；`I` 是大写字母 I，不是小写 l 或数字 1。

`S` 不表示一段长实体里的某个单字。多字实体不能因为“每个元素只有一个字”就全部标 `S`。

两字实体可以是 `B-prov E-prov`，例如“浙江”；三字实体是 `B-prov I-prov E-prov`；更长实体中间可以有多个 I。

不是所有类型都定义了 S。当前 1.0 没有 `S-prov`，所以不能擅自给单字省份缩写新增这个标签而继续使用原分类头。

## 3. 当前 1.0 的实体类型和全部标签编号

下表覆盖当前 `config.LABELS` 的全部 57 项。编号严格按文件顺序排列，不是按字母排序。

| 类型后缀 | 常见含义 | 本项目当前标签与编号 |
| --- | --- | --- |
| `O` | 非目标实体 | `O=0` |
| `assist` | 辅助定位描述，通常包括方位等 | `B-assist=1`，`I-assist=2`，`S-assist=3`，`E-assist=4` |
| `cellno` | 单元号 | `B-cellno=5`，`I-cellno=6`，`E-cellno=7` |
| `city` | 城市 | `B-city=8`，`I-city=9`，`E-city=10` |
| `community` | 小区、社区等细分地点名称 | `B-community=11`，`I-community=12`，`S-community=13`，`E-community=14` |
| `devzone` | development zone，开发区 | `B-devzone=15`，`I-devzone=16`，`E-devzone=17` |
| `district` | 区、县等 | `B-district=18`，`I-district=19`，`S-district=20`，`E-district=21` |
| `floorno` | 楼层号 | `B-floorno=22`，`I-floorno=23`，`E-floorno=24` |
| `houseno` | 房屋或房间编号等 | `B-houseno=25`，`I-houseno=26`，`E-houseno=27` |
| `poi` | Point of Interest，兴趣点或具体地点 | `B-poi=28`，`I-poi=29`，`S-poi=30`，`E-poi=31` |
| `prov` | province，省级行政区 | `B-prov=32`，`I-prov=33`，`E-prov=34` |
| `road` | 道路 | `B-road=35`，`I-road=36`，`E-road=37` |
| `roadno` | 道路门牌号 | `B-roadno=38`，`I-roadno=39`，`E-roadno=40` |
| `subpoi` | subordinate POI，地点中的下级或附属地点 | `B-subpoi=41`，`I-subpoi=42`，`E-subpoi=43` |
| `town` | 乡、镇、街道等 | `B-town=44`，`I-town=45`，`E-town=46` |
| `intersection` | 路口、交叉口 | `B-intersection=47`，`I-intersection=48`，`S-intersection=49`，`E-intersection=50` |
| `distance` | 距离描述 | `B-distance=51`，`I-distance=52`，`E-distance=53` |
| `village_group` | 村组 | `B-village_group=54`，`I-village_group=55`，`E-village_group=56` |

这些后缀的中文解释是根据名称和地址任务给出的常见含义。当前没有更细的标注规范，不能保证如 `assist/community/houseno/subpoi` 等在数据中的边界完全等同于日常用法。

例如“某小区某幢某室”应怎样拆分，需要由数据集标注规则统一决定，不能只靠模型或变量名猜测。


## 4. 怎样给训练数据使用这些标签

### 4.1 先确定片段，再逐字标注

以“浙江省杭州市”为例，概念上正确的标注是：

| 字 | 标签 | 当前 1.0 的编号 |
| --- | --- | --- |
| 浙 | `B-prov` | 32 |
| 江 | `I-prov` | 33 |
| 省 | `E-prov` | 34 |
| 杭 | `B-city` | 8 |
| 州 | `I-city` | 9 |
| 市 | `E-city` | 10 |

当前 1.0 的 TXT 格式示意：

```text
浙 B-prov
江 I-prov
省 E-prov
杭 B-city
州 I-city
市 E-city

文 B-road
三 I-road
路 E-road
9 B-roadno
0 I-roadno
号 E-roadno
```

空行表示两条不同样本。这里是格式示例，不是本轮创建的新训练文件，也不是建议用这两条示例重新训练。

### 4.2 `label2id` 把文字标签翻译成整数

处理器执行类似：

```python
label2id = {label: i for i, label in enumerate(config.LABELS)}
```

当前 `label2id["B-prov"]` 是 32。训练器处理的是整数张量，而不是字符串本身。

预测时方向相反：`config.LABELS[32]` 得到 `B-prov`。所以保存权重后不能随意重排标签列表，即使类别数量没变，也可能发生“能加载，但含义全错”的情况。

## 5. token 和标签如何对齐

### 5.1 token 不是永远等于一个汉字

token 是 tokenizer 分出来、模型实际读取的单位。汉字常常一字一个 token，数字、英文也可能合并或拆成子词；特殊字符还可能被过滤。

tokenizer 可以理解为“把文字换成模型能查的词典编号”的机器。这里的输入编号不是实体标签编号：一个说明“读到了哪个字”，另一个说明“这个字属于哪类”。

文档示例说明，普通处理 `0000号` 可能得到类似 `000/##0/号` 的分法。若原标注有 5 个字级答案，直接对上就错位。

代码先把字符串拆为字符列表，再传入 `is_split_into_words=True`，告诉 tokenizer：这是同一句话的预分割单位，不是多句独立文本。

### 5.2 `word_ids()` 是对照表

`word_ids()` 表明每个 token 来自原字符列表的哪一项。假设只有“浙江省”：

```text
token：     [CLS]  浙   江   省   [SEP]
word_id：   None   0    1    2    None
正确标签：  -100   32   33   34   -100
```

`[CLS]`、`[SEP]` 是模型使用的特殊 token，不是用户地址里的实体。`None` 表示没有对应的普通输入字。

`-100` 是交叉熵损失默认忽略的标签值，表示“这个位置不出题、不计分”，不是第 -100 个业务类别。补齐长度的 PAD，以及同一个原输入单位的后续子 token，也按本项目策略不计分。

### 5.3 当前 1.0 实际有一个保留的问题

当前函数判断 `if word_idx`，0 被当作假，因此上例实际会变为：

```text
当前代码：  -100  -100  33  34  -100
```

“浙”的监督信号被忽略。这个问题来自 1.0 原文档。上面的“正确标签”用于解释概念，不是在声称当前代码已经这样实现。

### 5.4 `attention_mask` 与标签掩码不同

`attention_mask` 通常用 1 表示真实 token，用 0 表示补齐位置。特殊 token 通常也是 1，但它们的 labels 可以是 -100，所以两个条件不能混为一谈。

像试卷上用于排版的页眉：模型可能会看到它，但我们不需要给它判“省份还是城市”。

## 6. 模型怎样用标签学习

一个批次的数据形状通常是：

```text
input_ids：      [batch, length]
attention_mask：[batch, length]
labels：         [batch, length]
BERT 输出：      [batch, length, hidden_size]
logits：         [batch, length, 57]
```

`batch` 是一次处理多少条地址，`length` 是 token 序列长度，`hidden_size` 是每个 token 的内部特征维度。本地 BERT 的 hidden size 是 768。1.0 训练入口的 batch 为 128，默认 length 为 64；最后一批可以小于 128。

“线性分类头”把每个位置的 768 个特征变成 57 个候选标签的分数，就像评委给 57 个选项分别打分。

`logits` 是未归一化分数，不是已经保证相加为 1 的概率。`CrossEntropyLoss` 接收 logits 和正确类别的整数编号；不需要先对 logits 做 softmax。标签通常以 `torch.long` 保存。

每步训练：

1. 前向计算：根据输入产生各标签分数。
2. 计算 loss：比较分数与标准标签，错误越严重通常惩罚越大。
3. 反向传播：计算参数对 loss 的影响方向。
4. 优化器更新：按学习率调整参数。

“学习率”决定每次调整多大。`Dropout` 在训练时随机屏蔽一部分特征，减少模型过分依赖单一线索；评估模式会关闭这种随机屏蔽。

## 7. 预测时标签怎样变成地址字段

```text
文本
 → tokenizer 的输入编号
 → BERT + 分类头的 57 类分数
 → argmax 选类别编号
 → LABELS[编号] 找到 B-prov 等标签
 → predict 去掉 B-/I-/E-/S-，得到 prov 等类型
 → address_alignment 按类型归并为业务字段
 → 数据库规范名称、补全上级
 → API 返回五字段 JSON
```

`argmax` 就是“最大值在哪里”，这里取分数最高标签的编号。

当前 1.0 的类型到业务字段映射：

| 预测类型 | 内部字段编号 | 返回字段 |
| --- | --- | --- |
| `prov` | 2 | 省份 |
| `city` | 3 | 城市 |
| `district` | 4 | 区县 |
| `road/intersection/town` | 5 | 街道 |
| `roadno/cellno/community/houseno/poi/subpoi/assist/distance/village_group/floorno/devzone` | 6 | 详细地址 |
| 空字符串，来自 `O` | 0 | 忽略 |

这里的 2、3、4、5、6 是后处理的字段层次编号，不是 `LABELS` 类别编号，也不是具体地区的 `region.id`。数据库中的行政层级有 1=国家、2=省级、3=城市级、4=区县级、5=乡镇街道级；详细地址 6 是程序自己的汇总位置。

去掉 BMES 前缀后，程序只知道“都是省份字”，不知道是哪一个省份片段的开头和结尾。当前算法按类型变化切段，再把片段赋给字段；同一输出字段后面的片段会覆盖前面的片段。

省份在接口和网页中都使用 `province` 字段；模型标签后缀仍叫 `prov`，二者由后端转换，不要求名称相同。

## 8. 哪些修改必须配套

本节只是说明规则，没有进行额外修改或训练。

- 新增标签：原始标注、标签表、分类头大小、训练数据缓存、预测解码和后处理都必须配套。
- 调整标签顺序：类别编号含义会改变，旧权重即使尺寸匹配也不能直接认为正确。
- 只想更换计算设备：改 `config.DEVICE` 即可，不需要改标签含义。
- 数据库存储从 MySQL 换为 SQLite：影响地区查询和初始化，不会自动给模型增加电话标签。

训练集用于更新参数，验证集用于选择模型，测试集用于最后衡量效果。可以把它们分别理解为平时练习、模拟考试和期末考试；反复看期末答案再调模型，会削弱最终测评的可信度。
