# 文件与函数说明

本文说明 1.0 项目的运行文件与自定义函数，不逐个展开第三方库或 `.venv` 内部函数。

## 1. 先认识几个词

| 名词 | 在本项目里的意思 | 可以怎样理解 |
| --- | --- | --- |
| 函数 | 接收输入，执行一组步骤，可能返回结果 | 一个有固定用途的小工具 |
| 类 | 把数据和相关函数放在一起的结构 | 一份工具箱的设计图 |
| 方法 | 定义在类里面的函数 | 工具箱提供的操作 |
| 参数 | 调用函数时传入的设置或数据 | 告诉工具处理什么、怎么处理 |
| 返回值 | 函数处理后交回的结果 | 工具交出的成品 |
| 入口 | 启动某个流程的位置 | 车间的开工按钮 |
| 继承 | 子类复用父类，再补上具体实现 | 用通用工具箱组装专用工具箱 |
| 抽象占位 | 函数先留接口，但直接调用会报 `NotImplementedError` | 留一个插座，等子类接上机器 |
| 副作用 | 除返回值之外，还保存文件、改对象或启动服务 | 工具除了交成品，还改动了工作台 |
| 异步 `async` | 能与异步等待机制配合的函数 | 可以在等待时让出调度机会；不代表里面的同步模型计算自动并行 |

## 2. 文件分工与调用关系

```text
config.py：公共设置
      ↓
main.py：训练流程调度
      ├─ models_def.py：创建模型、加载权重
      ├─ preprocess.py：读数据、token 对齐、划分、组装批次
      └─ train.py：反向传播、验证、测试、保存权重

app.py：接收网页请求
      ├─ templates/index.html：输入和展示
      ├─ models_def.py：模型预测
      └─ address_alignment.py：结构化、地区校验
               └─ data/region.db：地区名称与上下级关系

init_db.py：首次把 region.sql 转成 region.db
```

“训练”会更新模型权重；“推理”是使用已有权重回答新输入。`region.db` 不参与模型梯度训练，它在后处理阶段使用。

## 3. `config.py`：公共设置

该文件没有自定义函数，导入后提供一组变量。

| 变量 | 用途 |
| --- | --- |
| `BASE_DIR` | 项目根路径，其他数据目录从这里拼接 |
| `SQLITE_DB_PATH` | SQLite 地区文件 `data/region.db` |
| `REGION_SQL_PATH` | 首次建库时读取的 `data/region.sql` |
| `RAW_DATA_DIR` | 原始训练数据所在文件夹 |
| `PROCESSED_DATA_DIR` | 1.0 加工后数据目录 `data/processed` |
| `PRETRAINED_DIR` | 本地预训练模型目录 |
| `FINETUNED_DIR` | 微调权重输出目录 |
| `LOGS_DIR` | TensorBoard 日志目录 |
| `DEVICE` | 自动选择 CUDA → MPS → CPU；训练和默认预测共用 |
| `LABELS` | 有固定顺序的 57 个标签；列表下标就是类别编号 |

标签详解见文档 03。1.0 原本的 `MYSQL_CONFIG` 已被 SQLite 路径取代。

## 4. `models_def.py`：模型与预测

### `load_params(model, model_params_path)`

把磁盘上的参数读进已创建的模型，使用 CPU 映射和仅权重加载。文件不存在或属性错误时打印提示；分类头尺寸不匹配时，复用 BERT 参数，保留新模型刚初始化的分类头。它不返回加载成功标志，也不覆盖磁盘原权重。原文档的 CPU 重试写法已为运行兼容作最小调整。

“权重”是模型学到的一组数字。可以把模型结构看成房子布局，权重看成房内布置；分类头尺寸必须与 57 类标签表匹配，重新初始化的分类头需要训练。

### `AddressTagging` 类

| 方法 | 输入与作用 | 输出或副作用 |
| --- | --- | --- |
| `__init__(model_name, label_list)` | 加载 tokenizer 和 BERT，建立 dropout、线性分类头、交叉熵损失 | 创建待训练或待加载权重的模型；类别数取标签表长度 |
| `forward(input_ids, attention_mask=None, labels=None)` | BERT 将 token 编码，经过 dropout 和分类头；传入标签时计算损失 | 返回 `{"logits": ..., "loss": ...}`；自身不执行优化器更新 |
| `predict(text, device=None, batch_size=32)` | 接受一个字符串或字符串列表，切换到评估模式，移动到指定设备，分批预测 | 单条返回标签类型列表，多条返回列表的列表；不训练参数 |

`__init__` 是构造方法，创建对象时执行。`forward` 是 PyTorch 约定的方法，通常通过 `model(...)` 间接调用。

`predict()` 的 `@torch.inference_mode()` 关闭梯度记录，以减少推理开销。它使用 `argmax` 取每个位置分数最大的类别，再把 `B-prov` 去掉前两个字符，返回 `prov`。

当前原文档实现只把产生 token 的字符追加进结果，没有预先为原文每个位置保留空位；空格、特殊字符和截断可能使标签列表短于原文。它也没有返回概率或实体边界。

省略 `device` 时，在每次预测调用时读取 `config.DEVICE`；也可显式传入设备。

## 5. `preprocess.py`：把原始资料变成模型能学习的格式

可以把预处理看成整理习题册：先读取每道题及答案，再把文字换成数字，最后分为练习题、模拟题和期末题。

### `Processor`：通用处理器

| 方法 | 作用 |
| --- | --- |
| `__init__(data_path, save_dir, tokenizer, batch_size, max_seq_len, train_ratio=0.8, test_ratio=0.1)` | 保存数据位置、tokenizer、批大小、长度和划分比例 |
| `process()` | 调用具体数据构建方法，划分 train/valid/test，将三份数据保存到磁盘 |
| `get_dataloader(type, max_examples=None)` | 目录不存在时先加工；否则读取已有数据；可随机取一部分；返回 DataLoader。训练集打乱顺序，验证和测试不打乱 |
| `_make_dataset()` | 父类占位方法，要求子类实现具体的数据构建 |
| `_split_dataset(dataset)` | 先按 `test_ratio` 留出测试集，再按原总数的 `train_ratio` 选训练集，剩余部分为验证集；1.0 未指定随机种子 |

`type` 在这里是字符串，例如 `"train"`，不是给样本分类的标签。`DataLoader` 相当于按批次发题的工作人员，负责每次交给训练器一小批数据。

### `AddressTaggingProcessor`：地址任务处理器

| 方法 | 作用 |
| --- | --- |
| `__init__(..., label_list, max_seq_len=64, ...)` | 继承通用设置，建立 `label2id`：标签字符串到整数的映射 |
| `_make_dataset()` | 用生成器创建 Dataset，批量应用 `_map_fn()`，设置输出为 PyTorch 张量格式 |
| `_generate_examples()` | 读 `data.txt`；空行分隔样本，每个非空行拆为“词/字”和标签；读取时将 `name/phone` 临时映射为 `O`，`detail` 映射为 `poi`，再生成标签整数列表，逐条 `yield`；TXT 不修改 |
| `_map_fn(examples)` | 用 tokenizer 生成 `input_ids`、`attention_mask`，再根据 `word_ids()` 对齐标签，返回这三种训练输入 |
| `_align_labels_with_tokens(labels, word_ids)` | 普通词的首个子 token 取原标签，重复子 token 和特殊 token 设为 `-100`；当前保留首字编号 0 被忽略的问题 |

`yield` 表示每次交出一条数据，可以逐条生成；`map` 表示将同一个加工函数应用到一批样本。

当前读取 TXT：每行“文字 标签”，用空行分隔样本。

## 6. `train.py`：训练、验证与测试

### `Trainer`：通用训练器

| 方法 | 作用与结果 |
| --- | --- |
| `__init__(model, device, epochs, learning_rate, checkpoint_steps=200)` | 先将模型移到设备，再创建 AdamW 优化器 |
| `__call__(dataloader, model_params_path=None, writer=None, is_test=False)` | 让训练器对象能像函数一样调用；测试模式只跑测试，否则循环训练和验证，并按验证 F1 保存本轮运行的最佳权重 |
| `run_epoch(phase, epoch=0)` | 跑完一份数据；训练时清梯度、反向传播并更新参数，验证/测试时只计算；累计损失和指标，写日志；按步保存 `.checkpoint` |
| `forward(inputs)` | 通用占位，子类决定如何调用具体模型 |
| `update_records(inputs, outputs, records)` | 通用占位，子类决定保留哪些预测记录 |
| `compute_metrics(metrics, records)` | 通用占位，子类决定如何计算指标 |

`epochs` 是整份训练集重复学习几遍；`step` 是一次批次更新；`checkpoint` 是中途保存的权重快照。它像游戏存档，但本项目的存档没有包含优化器、累计轮次等全部进度。

`zero_grad()` 清掉上一步的梯度；`loss.backward()` 计算每个参数如何影响错误；`optimizer.step()` 据此调整参数。梯度可以理解为“朝哪个方向调整会减小错误”的局部提示。

### `AddressTaggingTrainer`：地址标注训练器

| 方法 | 作用 |
| --- | --- |
| `forward(inputs)` | 把 `input_ids/attention_mask/labels` 传给模型，返回模型输出与 loss |
| `update_records(inputs, outputs, records)` | 对 logits 做 argmax，只保留 attention mask 为 1 且标签不是 `-100` 的位置，收集预测和标准答案 |
| `compute_metrics(metrics, records)` | 拼接记录，用 sklearn 计算逐 token 的 precision、recall、macro F1，写入指标字典 |

precision 是“判为某类的有多少正确”，recall 是“真实属于某类的找回多少”，F1 综合这两者。macro 表示各类别先各自算分，再平等平均，而不是所有字符混在一起算一个准确率。

## 7. `main.py`：1.0 的训练调度入口

### `model_go(train=None, test=None, inference=None, model_params_path=None)`

依次创建模型、处理器和训练器，尝试加载传入权重；根据三个开关决定训练、测试和演示预测。1.0 固定训练 10 轮、批大小 128、学习率 `1e-5`。

训练输出权重使用带时间戳的文件名，便于区分运行。训练结束没有自动重载最优权重。推理演示使用文件内全局变量 `text`，打印“字符-标签类型”。

**文件底部直接调用 `model_go(...)`，没有 `if __name__ == "__main__"` 保护，导入该模块也会执行。** 这里保持文档原样。

## 8. `address_alignment.py`：字段提取与地区校验

| 函数 | 输入、处理和输出 |
| --- | --- |
| `address_alignment(text, model)` | 先预测标签；把细分标签映射到省、市、区县、街道、详细地址五类；按连续片段切原文；调用地区校验；返回五个中文字段的字典 |
| `check_address(region_type_id, address, parent_id=None)` | 就地修改 `address`，查询当前地区及父级，规范名称、补上级或清空冲突字段；必要时递归向上查询；返回布尔结果 |
| `query_parent(region_type_id, region_name, region_id=None)` | 用 SQLite 只读连接查询当前地区和父级；可按当前地区编号进一步限制；精确名称优先，否则取首项；返回字典或 `None` |

`label_map` 是“模型语言到业务字段”的翻译表。例如 `roadno/cellno/floorno` 等都归为详细地址。它不是 `label2id`，也不是数据库里每一条地区的编号。

递归就是函数为解决更小的一步，再调用自己。比如从永乐店镇查到通州区，再查到市辖区，再查到北京市，像顺着家谱往上找祖辈。

`query_parent()` 使用 `?` 占位符传入数据，不把用户输入拼成 SQL 语句结构。`mode=ro` 表示只读，避免查询路径错误时生成空库；`closing` 保证连接关闭。

脚本直接运行时先调用 `initialize_database()`，然后加载模型并处理内置样例。

## 9. `init_db.py`：SQLite 初始化工具

该文件是沿用已有的 SQLite 适配，不来自 1.0 的原 MySQL 实现。

| 函数 | 作用 |
| --- | --- |
| `region_inserts(sql_path)` | 从原地区 SQL 文件里提取针对 `region` 表的完整 INSERT 语句；跳过 MySQL 专用建表、设置；拒绝不支持或未结束的语句 |
| `initialize_database(sql_path=None, db_path=None)` | 已有非空库时直接复用；否则在临时数据库里建表、导入、检查完整性，成功后替换为正式文件；返回记录数；失败时清理临时文件 |

`SCHEMA` 是数据库表结构说明：规定每行有哪些列，并建立查询索引。索引像书后的检索目录，能减少查找工作。

原 SQL 文件仍是导入资料，不需要启动 MySQL 服务。首次初始化可能写库；后续已有库时不重新导入。

## 10. `app.py`：网页与 API 服务

| 对象或函数 | 用途 |
| --- | --- |
| `AddressAlignmentRequest` | Pydantic 数据模型，规定请求必须包含字符串 `message`；没有自定义方法 |
| `AddressAlignmentResponse` | 规定响应包含 `province/city/district/town/detail`，各项可以是字符串或 `None`；没有姓名电话，也没有自定义方法 |
| `homepage()` | 处理 GET `/`，返回 `templates/index.html` 文件 |
| `handle_message(request)` | 处理 POST `/address_alignment`，读取文本，调用 `address_alignment()`，把中文键转成英文响应字段 |

API 是程序之间约定的交接方式；JSON 是接口常用的键值数据格式；Pydantic 负责检查数据形状和类型。`None` 到 JSON 中变为 `null`，表示无结果。

文件导入阶段先初始化地区库、创建模型、加载权重，再建立服务。直接运行时由 Uvicorn 监听 8089 端口。`0.0.0.0` 表示监听可用网络接口；在本机浏览器访问通常用 `127.0.0.1`。

当前不兼容的旧权重会影响导入，因此不能仅凭语法检查认为服务已启动。

## 11. `templates/index.html`：网页输入与展示

HTML 定义页面元素，CSS 定义外观，JavaScript 处理交互。该文件没有随 1.0 Python 代码重新替换。

| 函数或回调 | 作用 |
| --- | --- |
| `marked.setOptions()` 中的 `highlight(code)` 匿名函数 | 尝试调用 `hljs.highlightAuto()` 给代码着色；页面没有引入 hljs，存在潜在问题，是否触发还取决于 marked 版本与输入 |
| 输入框 `input` 事件回调 | 根据内容自动调整输入框高度 |
| 输入框 `keydown` 事件回调 | Enter 发送，Shift+Enter 保留换行 |
| `createLoadingBubble()` | 创建“正在思索中...”提示元素，返回 DOM 节点 |
| `addMessage(content, isUser)` | 将用户消息或结果加入聊天区；结果用 marked 转为 HTML，再经 DOMPurify 处理后展示；最后滚动页面 |
| `sendMessage()` | 获取文本，禁用按钮，发 POST 请求，读取 JSON，将字段整理成列表；处理请求异常，移除加载提示并恢复按钮 |

DOM 是浏览器表示页面元素的对象结构，可以把它理解为程序能够操作的页面积木。

`sendMessage()` 读取 `province/city/district/town/detail` 五个响应字段，与接口一致。它没有先判断 `response.ok` 再解释响应，这个既有逻辑保留。
